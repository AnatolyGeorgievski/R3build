# board — железо плат

Как в корневом README r3build: профиль (`profiles/`) ≠ плата (`board/`).

Концепция стенда (полка · netboot · коммутация · электрощит): [`docs/R3_STAND.md`](../docs/R3_STAND.md).

## Как начинаем

Стенд и новый проект часто стартуют с **готового одноплатника** (Radxa / Orange Pi / RasPi): рабочая загрузка вендора, сеть, отладка. Свой `/init`, netd, mcp, gpio — **добавляем в загрузку** или меняем её, когда контур уже жив. Своя плата / свой SoC — следующий шаг, не обязательная точка входа.

Макет полки ([[george]] 04.11): **три разные** платы; одна — **коммутация** (питание/реле) → горизонт **умный электрощит**. DUT и мозг кнопок не на одной плате.

| | сейчас | позже |

| **zynq7000/** | DTS/DTB + NAND-патч | образ/профиль под стенд по слову |
| **radxa/** · **orange/** | слоты README; модели 5C/2F/3B в работе | dts/скрипты/образ по мере хода |
| **bb/** · **cv18x/** | место в карте (не списываем) | дерево, когда появится железо/сборка |
| **profiles/** | живой `ant/` | `herd`/`swarm` — когда нужен отдельный rootfs-тип |

## Референс стендов (готовые SBC)

| каталог | модели в работе | роль |
|---------|-----------------|------|
| `radxa/` | ROCK 5C · 2F · 3B | стенд / полка; старт с вендорной загрузки |
| `orange/` | Orange Pi (линейка в лабе) | то же |
| `rpi/` | Raspberry Pi (3 B+ и др.) | то же; gpio/MCP — см. `godminer/src/board_rpi.h`, образ из r3build |

Подкаталоги моделей (`radxa/5c`, `radxa/2f`, `radxa/3b`, …) — по мере dts/скриптов/образа; пустое место не заполнять выдумкой.

Пустой слот ≠ списан.
