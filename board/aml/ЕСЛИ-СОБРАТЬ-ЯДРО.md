# Если Борис (или Макс) захочет собрать ядро A113D

<tags>aml, ядро, борис, макс, сборка, коллаборант</tags>

Краткий ответ: **да, ядро (Image.gz + dtb) собрать можно** из `board/aml/` по разделу README «Сборка отдельно, на Linux».  
Это **не** весь путь до прошивки платы (шифрованный boot на mtd4, rootfs, USB-burn).

## Условия доступа

| условие | статус |
|---------|--------|
| Write на GitHub `AnatolyGeorgievski/R3build` | `smalldaemon` (Борис), `taygoth` (Макс) |
| Ветка с `board/aml/` на origin | нужна **push** с нашей стороны (локально коммиты могут быть ещё не запушены) |
| Скрипты `./kernel/fetch_source.sh` / `build_kernel.sh` | **нет** в этом репо — Docker-путь из README Макса здесь **не** работает |
| Рабочий путь | только «Сборка отдельно, на Linux» из каталога `board/aml/` |

## Что уже лежит в git (достаточно для ядра)

Из корня клона:

- `board/aml/source.lock` — Linux **6.18.42**, URL + SHA-256  
- `board/aml/patches/` + `series` — три патча  
- `board/aml/dts/meson-axg-a113d-miner-production.dts`  
- `board/aml/configs/a113d-production.config`  
- `board/aml/README.md` — полные команды  

Публичный SSH ключ платы (`alpine/aml_devboard_ed25519.pub`) — для опознания; **приватного ключа в git нет**.

## Чего в git нет (и зачем)

| нет | следствие |
|-----|-----------|
| `Image.gz` / готовый dtb | не скачать артефакт — **собрать самому** (так и задумано) |
| `./kernel/*.sh` / Docker-сборка | не вызывать; идти Linux+cross |
| private `aml_devboard_ed25519` | на плату по SSH этим ключом из репо не войти |
| usb-boot `.enc` / `.img` (~40 МБ) | SD-прошивку из репо не повторить; файлы у Макса / локально у нас |
| rootfs / FIT / AMLSECU-упаковка | до «второго boot в mtd4» одним `make` не дойти |

## Хост и пакеты (Debian/Ubuntu)

```text
build-essential gcc-aarch64-linux-gnu bc bison flex
libssl-dev libelf-dev dwarves cpio rsync device-tree-compiler
patch curl xz-utils
```

Нужен выход в интернет: `cdn.kernel.org` (~150 МБ tar.xz). Диск: лучше ≥5–8 ГБ свободно под распаковку и `O=build`.

## Пошагово (как у нас сработало)

```sh
git clone git@github.com:AnatolyGeorgievski/R3build.git
cd R3build/board/aml

# пустой каталог сборки рядом с board/ → R3build/a113d-build/
set -eu
SERIES_DIR=$(pwd)
. "$SERIES_DIR/source.lock"
mkdir -p ../a113d-build
cd ../a113d-build
test ! -e "linux-$KERNEL_VERSION"
test ! -e build

curl --fail --location --retry 3 -o "$KERNEL_ARCHIVE" "$KERNEL_URL"
printf '%s  %s
' "$KERNEL_SHA256" "$KERNEL_ARCHIVE" | sha256sum -c -
tar -xJf "$KERNEL_ARCHIVE"
SOURCE_DIR="$PWD/linux-$KERNEL_VERSION"
BUILD_DIR="$PWD/build"

while IFS= read -r name || [ -n "$name" ]; do
  case "$name" in ''|#*) continue ;; esac
  patch --batch --forward --fuzz=0 -d "$SOURCE_DIR" -p1     -i "$SERIES_DIR/patches/$name"
done < "$SERIES_DIR/patches/series"

cp "$SERIES_DIR/dts/meson-axg-a113d-miner-production.dts"   "$SOURCE_DIR/arch/arm64/boot/dts/amlogic/"

export ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
export KBUILD_BUILD_USER=a113d-devboard KBUILD_BUILD_HOST=container
export KBUILD_BUILD_TIMESTAMP='1970-01-01 00:00:00 UTC' SOURCE_DATE_EPOCH=0

make -C "$SOURCE_DIR" O="$BUILD_DIR" defconfig
"$SOURCE_DIR/scripts/kconfig/merge_config.sh" -m -O "$BUILD_DIR"   "$BUILD_DIR/.config" "$SERIES_DIR/configs/a113d-production.config"
make -C "$SOURCE_DIR" O="$BUILD_DIR" olddefconfig
make -C "$SOURCE_DIR" O="$BUILD_DIR" -j"$(nproc)"   Image.gz amlogic/meson-axg-a113d-miner-production.dtb
```

### Приёмка «ядро собралось»

Файлы должны появиться:

- `a113d-build/build/arch/arm64/boot/Image.gz`
- `a113d-build/build/arch/arm64/boot/dts/amlogic/meson-axg-a113d-miner-production.dtb`

Байт-в-байт с нашей сборкой **не** обещать (версия кросс-gcc влияет) — канон: те же `source.lock` + патчи + config + явные цели make.

На macOS без своей Linux/VM этот рецепт не канон; Docker-скриптов Макса в R3build нет.

## Что это даёт Борису по смыслу продукта

| да | нет |
|----|-----|
| Повторить **production-ядро** A113D из открытой серии | Готовый зашифрованный образ на **mtd4** |
| Проверить, что серия в R3build целая | Rootfs / FIT / miner + MCP на AML «из коробки» |
| Общий язык с Максом по Image.gz/dtb | SSH на стенд без отдельной выдачи ключа |

Дальше (mtd4 / AMLSECU / aml_boot) — отдельные зачатки у нас в godminer; координация с Максом/Алексом, не этот README.

## Граница

Write на R3build ≠ доля в зерне/netd. Серия ядра — донат/стенд Макса в контуре сборки; кодом продукта наружу по старой договорённости не размазывать. Борису можно собирать **ядро из board/aml**, не выдавая это за «весь AML-продукт готов».

## Нам перед его попыткой

1. `git push` origin (чтобы `board/aml/` был на GitHub).  
2. При желании — одна фраза Борису: «ядро: `board/aml/ЕСЛИ-СОБРАТЬ-ЯДРО.md`, путь Linux+cross; Docker-скриптов в репо нет».
