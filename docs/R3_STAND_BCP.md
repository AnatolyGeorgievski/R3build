> Это текст **для людей**: зачем полка, чему учил Митя, что уже сделано, что делаем дальше. Норматив коротких правил — `R3_STAND.md`. Сборка rootfs — `R3_BCP.md`. Здесь — связный урок и горизонт силы.

## Зачем стенд

Образ без полки — теория. Стенд — место, где образ **приходит по сети**, плата отвечает по **MCP**, кнопки силы идут через **gpio**, а не через выдёргивание шнура каждый раз.

Три имени одного предмета (уже в каноне):

| имя | для кого звучит |
|---|---|
| полка отладки | инженеру софта: много плат, один host, меняем только payload |
| макет | тем, кто ещё на столе: доказать топологию до шкафа |
| электрощит | продукту: реле и сценарии вкл/выкл — горизонт из платы коммутации |

Стенд живёт в **r3build**: здесь собирают `/init`, ramdisk, профили `board/`. Не отдельный «умный дом ради умного дома».

## Урок Мити · организация стенда

Митя (umbar / cdba) показал модель, которую мы приняли:

1. **Host толкает образ** (у него — fastboot/`boot.img`; у нас — **TFTP + тонкий stub на SD**). Карту каждый раз не перешиваем.
2. Сначала сеть и **netd**, в нём **MCP** — им пользуется агент с host (`[[cursor]]` на arc2).
3. Кнопки — не новый демон «как cdba», а **MCP → gpio** на плате коммутации.
4. PPPS-хабы с рынка (**MEGA-4** и проч.) — **референс**, не наш заказ: силу паяем / собираем на месте.
5. Мечта «ядро + USB-C выкидыши (питание · сеть · UART)» — смотреть, не копировать закупку.

**Контракт выполнен (факт на 2026-11-07):**

| кто | что сделал | как узнать готово |
|---|---|---|
| [[cursor]] + [[george]] | три Raspberry Pi 3 B+ на stub → TFTP → netd MCP | `.82` / `.83` / `.84` · `:8443` · tool `gpio` |
| host arc2 | dnsmasq + `/srv/tftp/rpi` · IP по MAC | journal PXE · MES `gi1/0/13–15` |
| образ | `scripts/mk-rpi-netd-ramdisk.sh` · `board_rpi.h` | `tools/call` gpio get BCM 17/27 |

Урок организации стенда **закрыт**: цикл «stub → сеть → MCP → gpio» живой на трёх одинаковых платах. Дальше — не объяснять модель, а **наращивать силу**.

## Связанные технологии (коротко)

| слой | что это здесь |
|---|---|
| **BCP образа** | Alpine miniroot / busybox + **netd** (+ dropbear на других SoC) — см. `R3_BCP.md` |
| **netboot** | `bootcode.bin` на SD; ядро · dtb · initrd с TFTP — как fastboot без USB-гаджета |
| **MCP** | JSON-RPC на TCP `:8443`; applets netd (в т.ч. `gpio`) |
| **gpio** | char-dev `gpiochip` · BCM-номера · профиль `board_rpi.h` |
| **zcip / static** | адрес до MCP; на Pi-тройке — static по MAC (`.82–.84`) |
| **I2C expander** | следующий слой ног: больше линий, чем даёт чип Pi, под реле |
| **PPPS** | управляемое питание слота (хаб/плата силы); референс рынка — MEGA-4; наш — паять и вести с MCP |

GPU/CUDA (ночной train) — **другой** контур железа. Стенд BCP про платы, провода и кнопки, не про сервер с PRO 4000.

## Что дальше · прямая речь

Урок Мити по организации выполнен. Дальше автоматизация силы и релейные выходы.

### 1. PPPS · питание слота

**Кто:** [[cursor]] проектирует цепочку в образе и MCP; [[george]] паяет/ставит железо PPPS и говорит, когда слот под током.  
**Что:** с host через MCP погасить и поднять питание DUT (холодный цикл без руки на штекере).  
**Где:** плата коммутации на полке (не тот же чип, что DUT).  
**Готово, когда:** команда MCP → слот обесточен → снова под током → плата снова берёт TFTP/MCP.  
**Не делаем:** заказ готовых PPPS-хабов «как у Мити»; чужой umbar как наш код.

### 2. Релейные выходы · gpio + I2C port expander

**Кто:** [[cursor]] добавляет в netd/MCP путь `gpio` → I2C expander → реле; [[george]] выбирает чип expander и плату реле, подключает линии.  
**Что:** дискретные выходы 12 В / сухой контакт / оптрон — сценарии щита.  
**Где:** те же Pi (или выделенная плата коммутации) · шина I2C · expander (PCA / MCP23xx — модель открыта до слова [[george]]).  
**Готово, когда:** `tools/call` включает и гасит названный канал реле; на MES/мультиметре виден факт.  
**Не делаем:** веб-витрину щита; авто-discover всего поля.

### Порядок

1. Держать тройку Pi живой (образ один на TFTP).  
2. PPPS на одном слоте — приёмка силы.  
3. Expander + одно реле — приёмка выхода.  
4. Размножить каналы под макет щита.
