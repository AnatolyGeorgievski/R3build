# 2026-10-13 — сборка образа Alpine

Корень сборки — домашний каталог учётной записи:

```
CWD=/home/{name}
```

Дальше пути от `$CWD`. Имя учётной записи в репозиторий не пишется.

Этот файл — начало работы над образом. Следующая сессия читает его до любой команды `apk`, `cpio`, `mkimage` и до любой записи в живой rootfs. Неверный rootfs, прошитый на плату, закирпичивает железо. Здесь кирпич — не метафора: плата может перестать грузиться.

Канон шага: 🧩 одна стыковка, без разрастания одного файла. 🧱 базовый блок образа — пакет Alpine и файл профиля, не новый апплет в godminer.

## Жёсткий контракт

1. Живые деревья не стирать и не пересобирать поверх: `$CWD/rootfs-aarch64`, `$CWD/rootfs-armv7`, `$CWD/rootfs-armhf`, `$CWD/rootfs-antminer`, `$CWD/alpine`. Проба apk — только в `/tmp/apk-trust-*`.
2. На плату ничего не писать. Не вызывать `flash_erase`, `nandwrite`, `mkimage` и не писать на плату в локальной сети. `fw-update.sh` не входит в `rcS`.
3. `rm -rf "$ROOTFS"` в `alpine-rootfs.sh` остаётся закомментированным. Скрипт делает `mkdir -p` и `apk add` в указанный каталог.
4. Пакеты после `alpine-keys` ставятся только с проверкой подписи. `--allow-untrusted` разрешён один раз: на сам пакет `alpine-keys`, пока каталога ключей ещё нет. Дальше `--keys-dir "$ROOTFS/etc/apk/keys" --no-script --no-cache` без `--allow-untrusted`.
5. OpenRC нет. Postinst Alpine (`rc-update`) на чужой архитектуре без эмуляции падает. Поэтому `--no-script`.
6. Точка входа: ядро → `/sbin/init` (busybox) → `/etc/inittab` → `sysinit:/etc/init.d/rcS`, останов → `shutdown:/etc/init.d/rcK`. Сценарии только LF. После копирования `chmod +x` на `rcS` и `rcK`. Если `inittab` нет или `rcS` не исполняемый, ядро молчит.
7. `rcS`, `inittab` и старт `netd` живут в образе, не как новый апплет godminer. Вытеснение busybox (`ntpd`, `zcip`, `mkdir`, `mount`, `ubiattach`, `cp`, `ln`, `test`) — подмена symlink через `netd --install` после `netd --selftest`, без правки `rcS` на каждом шаге.
8. Каталог `init.d` git не видит: в `.gitignore` строка `*.d` совпадает с именем каталога. Файлы `profiles/ant/etc/init.d/rcS` и `rcK` лежат на диске и в `$CWD/r3build.local`. В коммит контракта они добавлены через `git add -f`. Маска `*.d` не менялась: новый файл в `init.d` снова будет скрыт. Не считать их «лишними» и не удалять.

## Чего не делать следующим движением

- Не запускать git-версию `install-init.sh`: сломанный `SRC=` и упаковка ramdisk/`mkimage`.
- Не копировать профиль ant поверх живого `rootfs-*`.
- Не менять `.gitignore` `*.d` вместе с прошивкой. Сценарии уже в коммите через `git add -f`; маска по-прежнему прячет новые файлы.
- Соседние деревья `$CWD/godminer` и `$CWD/R3-net` в этот репозиторий не класть.

## ubi в ядре, не в Alpine

`ubi` и `ubifs` входят в сборку ядра. Их не подгружают. В пакетах Alpine этих модулей нет, и в rootfs их не кладут. Модули образа — только те, что приходят из Alpine. `rcS` вызывает `ubiattach` и `mount -t ubifs` без `modprobe`.
Тома `/config`, `/sn`, `/nvdata` опциональны.

На arc2 своей NAND нет. Проверка — чип в памяти, 64 МиБ: `modprobe nandsim first_id_byte=0x20 second_id_byte=0x36`. В `/proc/mtd` имя должно быть `NAND simulator partition 0`. Иное имя — стоп, это не симулятор. Дальше `ubiformat -y /dev/mtd0`, `netd ubi attach -m 0 -b 4`, три `ubimkvol` по 8 МиБ (`config`, `sn`, `nvdata`), `netd mount -t ubifs` и `netd umount` в `/tmp/ubi-vol/…`, затем `netd ubi detach -d 0` и `rmmod nandsim`. На этом ядре `ubi` и `ubifs` — модули. В ядре платы они встроены.
Существующий образ собран поверх minimal rootfs Alpine. На железе сейчас дерево `$CWD/rootfs-armv7`. Девять файлов профиля `ant` там есть, байты те же. В профиле `init` тоже `755`. Скрипт после копии всё равно ставит `+x` на `init`, `rcS`, `rcK`, `sbin/netd` и `root/e9pro`. `sbin/init` — ссылка на `bin/busybox`. World: alpine-baselayout, alpine-keys, alpine-release, apk-tools, busybox, ca-certificates, dropbear, dropbear-scp, mtd-utils-flash, mtd-utils-ubi, musl-utils.
В профиль `ant` входят каталоги `config/` и `schema/`: `config/config.json`, `config/mcp.json` (манифест netd), `schema/config.json`. `netd` ищет `config.json` сначала в `config/`, `mcp.json` — в `/etc`, затем в `config/`. `e9pro` открывает те же относительные пути `config/` и `schema/`, рабочий каталог — корень образа. Бинарник `netd` кладётся в `/sbin` без `--install`. `e9pro` кладётся в `/root`. В этот шаг бинарники не копировались.
🧩 В `$CWD/rootfs-armv7` положены `/sbin/netd` и `/root/e9pro` без `--install`, плюс `config/` и `schema/` из профиля. `qemu-arm -L` этого дерева: `netd --selftest` ok. Ребут платы не делался.
