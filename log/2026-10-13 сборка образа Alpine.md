# 2026-10-13 — сборка образа Alpine

Этот файл — начало работы над образом. Следующая сессия читает его до любой команды `apk`, `cpio`, `mkimage` и до любой записи в живой rootfs. Неверный rootfs, прошитый на плату, закирпичивает железо. Здесь кирпич — не метафора: плата может перестать грузиться.

Канон шага: 🧩 одна стыковка, без разрастания одного файла. 🧱 базовый блок образа — пакет Alpine и файл профиля, не новый апплет в godminer.

## Жёсткий контракт

1. Живые деревья не стирать и не пересобирать поверх: `/home/george/rootfs-aarch64`, `/home/george/rootfs-armv7`, `/home/george/rootfs-armhf`, `/home/george/rootfs-antminer`, `/home/george/alpine`. Проба apk — только в `/tmp/apk-trust-*`.
2. На плату ничего не писать. Не вызывать `flash_erase`, `nandwrite`, `mkimage` и не трогать майнер `192.168.1.133`. `fw-update.sh` не входит в `rcS`.
3. `rm -rf "$ROOTFS"` в `alpine-rootfs.sh` остаётся закомментированным. Скрипт делает `mkdir -p` и `apk add` в указанный каталог.
4. Пакеты после `alpine-keys` ставятся только с проверкой подписи. `--allow-untrusted` разрешён один раз: на сам пакет `alpine-keys`, пока каталога ключей ещё нет. Дальше `--keys-dir "$ROOTFS/etc/apk/keys" --no-script --no-cache` без `--allow-untrusted`.
5. OpenRC нет. Postinst Alpine (`rc-update`) на чужой архитектуре без эмуляции падает. Поэтому `--no-script`.
6. Точка входа: ядро → `/sbin/init` (busybox) → `/etc/inittab` → `sysinit:/etc/init.d/rcS`, останов → `shutdown:/etc/init.d/rcK`. Сценарии только LF. После копирования `chmod +x` на `rcS` и `rcK`. Если `inittab` нет или `rcS` не исполняемый, ядро молчит.
7. `rcS`, `inittab` и старт `netd` живут в образе, не как новый апплет godminer. Вытеснение busybox (`ntpd`, `zcip`, `mkdir`, `mount`, `ubiattach`, `cp`, `ln`, `test`) — подмена symlink через `netd --install` после `netd --selftest`, без правки `rcS` на каждом шаге.
8. Каталог `init.d` git не видит: в `.gitignore` строка `*.d` совпадает с именем каталога. Файлы `profiles/ant/etc/init.d/rcS` и `rcK` лежат на диске и в `/home/george/r3build.local`. В коммит контракта они добавлены через `git add -f`. Маска `*.d` не менялась: новый файл в `init.d` снова будет скрыт. Не считать их «лишними» и не удалять.

## Что уже проверено

`apk.static` во временных деревьях, не в живых rootfs.

Порядок, который прошёл:

```sh
apk --arch "$ARCH" --root "$ROOTFS" --initdb add
apk ... --allow-untrusted add alpine-keys
# дальше без --allow-untrusted
apk ... --keys-dir "$ROOTFS/etc/apk/keys" --no-script --no-cache add busybox
```

- `alpine-devel@lists.alpinelinux.org-616adfeb.rsa.pub`

## Чего не делать следующим движением

- Не запускать git-версию `install-init.sh`: сломанный `SRC=` и упаковка ramdisk/`mkimage`.
- Не копировать профиль ant поверх живого `rootfs-*`.
- Не менять `.gitignore` `*.d` вместе с прошивкой. Сценарии уже в коммите через `git add -f`; маска по-прежнему прячет новые файлы.
- Не слать `c2063f2` и не коммитить R3-net и r3build, пока об этом не попросят.
